# Compose resource preflight

`go run ./cmd/compose-preflight -input preflight.json` produces a reviewable JSON report. The input contains a reduced Compose resource model and a host snapshot; it must not contain resolved Compose output, environment values, credentials, or raw command output. Unknown input fields are rejected and error text is deliberately generic.

Stack `configurationAssets` separately identify portable configuration, persistent data, host-provided files, and host devices by path and class; persistent data must link a backup policy. The server profile schema separately declares shared host requirements, including explicit managed-resource intent, mountpoint expectations, device requirements, minimum versions, environment input names, and registry hosts. The caller merges those declarations with network, volume, bind, port, and device requirements from the normalized Compose model. The API at `internal/composepreflight` is the reusable entry point for agent and server integrations. `Evaluate` always treats snapshots as supplied. An authenticated server integration may call `EvaluateObserved` only after it authenticates the target agent and checks the snapshot binding to the requested profile and assignment; the package does not authenticate callers itself. Callers should derive `RequirementModel` from a trusted Compose-normalized model without retaining environment values, then attach a recent `HostSnapshot` collected by the target agent. Snapshots are accepted as verified evidence only when `source` is `observed-agent`, `complete` is true, collection succeeded, and `capturedAt` is within five minutes. A supplied or stale snapshot is clearly labeled and all host-dependent checks remain unknown; the CLI forcibly labels JSON snapshots as supplied, so a report from it is a plan for review and cannot claim target-host readiness.

The snapshot uses safe inventory fields only: Docker/Compose versions, network and volume identity/driver, sanitized path and exact mountpoint observations, listening port ownership, device availability, environment-input availability, registry prerequisite availability, and backup-policy availability. The collector must omit raw environment values, registry credentials, Compose output, and error text. `ObserveBindPath` must run on the target agent and consumes Linux `/proc/self/mountinfo` locally. It returns only sanitized path state and the exact active mountpoint. A bind path is resolved against `projectDirectory`, including symlinks; relative paths that resolve outside that directory are blocked. `requireMountedFilesystem` must name the expected profile mount path, such as `/mnt/data`; only that exact mount boundary satisfies the requirement. An unrelated parent filesystem or merely creating the directory does not satisfy it.

Missing explicitly managed networks or volumes are reported as `planned` for a later separately approved apply. Missing external/shared resources block readiness. Existing resources are only reported as preserved; this package has no apply, restart, prune, delete, mount, format, or provisioning operation. A missing managed resource keeps `ready` false until the resource is provisioned through a separately approved apply and a fresh snapshot confirms it is present.

Port checks treat an occupied port as reusable only when both stable Compose project and service identities match; other known owners are conflicts. Unknown port ownership blocks. Host networking and device access are explicit requirements. Missing evidence for any required capability blocks with an `unknown` finding instead of passing.

This command deliberately reads only caller-supplied files and does not contact Docker or a remote server. Production readiness requires an authenticated agent integration to supply fresh observations from the assigned target; local manually authored snapshots remain unverified.
